# 領域規則參考

`checker.py` 每條規則的依據。此檔僅供理解與向使用者解釋，
**判斷仍由腳本執行**。

## 文件一致性（R1–R8）

三單（Invoice、Packing List、B/L）描述的是同一票貨，
因此下列數值必須互相吻合。人工比對做的就是這件事，
但欄位分散在多頁、數字相近，是典型的注意力衰減場景。

| 規則 | 檢查 | 出錯的後果 |
|---|---|---|
| R1 | 文件編號一致 | 後續往來引用錯誤單號，追查困難 |
| R2 | 文件日期一致 | 版本混淆，可能沿用作廢文件 |
| R3 | 櫃數 = 申報櫃數 | 漏列櫃號導致提貨或申報短少 |
| R4 | 逐櫃件數加總 = 表尾件數 | 申報數量不符，須事後更正 |
| R5 | 逐櫃重量加總 = 表尾重量 | 與船公司 SO 總毛重不合，須重出文件 |
| R6 | 淨重 < 毛重 | 淨重等於毛重代表未計包裝重，屬填寫瑕疵 |
| R7 | Packing List 數量 = Invoice 數量 | 完稅價格計算基礎錯誤 |
| R8 | 數量 × 單價 = 金額 | 申報價格錯誤，涉及稅基 |

R5、R6 為實務高頻問題：供應商常沿用舊 Excel 範本，
錯誤會被複製繼承到往後每一票，而非單次疏忽。

## 完稅價格（R9、R10）

台灣進口貨物完稅價格以 **CIF** 為基礎。
貿易條件若為 EXW、FOB、CFR 等，須另行加計未含之運費與保險費。

- 文件僅載明 FOB 價與運費、未載保險費時，須向進口人確認實付保費。
- 貨價與運費幣別不同時，須分別依海關公告之當旬匯率換算，
  不可先合併再換算。

## 原產地與輸入規定（R12）

原產地認定看**貨物生產地**，不看裝船港。
自香港轉口的中國大陸貨物，原產地仍為中國大陸。

中國大陸物品有輸入規定限制，部分貨品須事先申請輸入許可，
**申請作業需時**。若於貨物抵港後才發現需許可，貨櫃將滯留港區，
產生延滯費（DEM）與貨櫃留滯費（DET），
嚴重時須辦理退運至第三地再進口，成本包含額外運費、倉儲與人力協調。

因此本規則的正確使用時機是**裝船前**，而非到貨後。

部分鋼鐵製品另有反傾銷稅或平衡稅措施，
適用與否可能取決於材質與規格細節（例如鍍鋅鋼板厚度），
此類判斷依賴資深人員的經驗，屬應優先文件化的隱性知識。

## 稅則號列（R13）

- HS Code 為國際通用前 6 碼；台灣進口申報須用 **11 碼 CCC 號列**。
- 供應商在 Invoice 上標示的 HS 係其出口國申報，
  可作為縮小檢索範圍的候選值，**不得直接沿用**。
- 申報責任在進口人與報關人，歸列錯誤可能導致補稅或罰鍰。
- 品名欄常為料號或型號（例如 `UA420-BT`），不含材質資訊，
  無法據以歸列；實務上應建立料號對照歷史報單的產品主檔。

## 稅則查詢輔助工具與規定代號複查（R16）

`scripts/tariff_lookup.py` 對 112 年版稅則合訂本（上冊＋下冊）建立的
`data/tariff.db` 做關鍵字查詢，回傳候選 CCC 號列與其輸出入規定代號說明。
**這是檢索工具，不是歸列引擎**：關鍵字比對永遠可能有多個候選、也可能漏掉
真正對的那筆（例如品名用「加工方式＋用途」描述時，常常搜不到稅則慣用的
概括性分類詞彙），最終歸列責任完全在報關人員，跟 R13「供應商標示 HS 僅為
候選值」是同一個定位，不能因為多了一個查詢工具就把候選當成答案。

`R16` 只在 Invoice 已有人工填入的 `confirmed_ccc_code` 時執行，做的是
單純查表——該號列在稅則書上寫的輸出入規定代號是什麼——本身不做任何
比對或推論，因此屬於 `checker.py` 的確定性保證範圍；「這個品名該歸哪個
號列」則永遠不屬於 `checker.py` 的職責，只能由 `tariff_lookup.py` 提供
候選、由人（或模型讀候選後解釋）判斷。

`confirmed_ccc_code` 不是抽取欄位，`extract.py`（不論規則式或視覺路徑）
都不會填這個欄位；它只在使用者看過 `tariff_lookup.py` 的候選、確認要
採用某個號列後，才由人工（或模型代為）寫入 JSON。

**已知涵蓋範圍缺口**：`tariff.db` 只涵蓋稅則本身印刷的輸出入規定代號
（一般許可管制，如食品、藥品、槍枝、CITES 保育類動物等）。經濟部國際
貿易署另行公告的「戰略性高科技貨品」「兩用貨品」清單及禁運國別管制，
不在此資料庫範圍內，`tariff_lookup.py` 的輸出會固定提醒此點，
但實務判斷仍須另行查核，不能只依賴本工具。

## 櫃號格式（R11）

ISO 6346：4 個英文字母（擁有者代碼 3 碼 + 種類代碼 1 碼）
加 7 位數字（序號 6 碼 + 檢核碼 1 碼）。
格式不符通常為繕打錯誤。

（註：本規則目前僅檢查格式，尚未驗算檢核碼。）

## 進出口方向（影響 R9、R12、R14、R15）

同一套文件，申報方向不同，適用規則相反。

| | 進口 | 出口 |
|---|---|---|
| 申報價格基礎 | CIF（須加計運費、保險費） | FOB（CIF 條件須扣除運保費） |
| 管制查核 | 輸入規定代號、輸入許可、反傾銷／平衡稅 | 輸出許可（管制品：化學品、食品、醫療器材等） |
| 第三份文件 | B/L（換 D/O 後方能申報提貨） | SO／訂艙確認書（B/L 於裝船後才簽發） |
| 時序 | 貨到港 → 換單 → 申報 → 繳稅 → 放行 | 文件 → 申報 → 核放 → 進倉裝船 → 取得 B/L |

出口申報時**尚無 B/L**，因此 R14／R15 應以 SO 核對。
若在出口案例中要求提供 B/L，是流程理解錯誤。

海運進口的換單（正本 B/L → D/O）需 1–3 個銀行工作日，
是進口最容易延誤的環節；電子提單或電報放貨可縮短此段。

出口截關：FCL 一般開航前 1–2 個工作日，LCL 需提前 3–5 日；
空運於起飛前 2–3 小時截關。管制品許可建議提前 3–5 個工作日確認。
